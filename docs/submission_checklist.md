# Manual submission checklist

This is a review guide, not a packaging script. The final audit prompt specifies the names below. The coursework PDF uses a different ZIP spelling (`UoG-PMCOA.zip`) and a different folder pattern (`UoG-PMCOA_Groupxx`), so confirm the exact required naming with the course portal before packaging and record the decision.

## Names and files

- [ ] Submission folder: `UoG-PMCOAGroup05`
- [ ] ZIP: `UoG-PMCOA.zip`
- [ ] Report: `PMCOAReportGroup05.pdf`
- [ ] Include the C source and headers for Stage 0, baseline, variants v0–v10, replay and support code; include required `.S` sources and C reference/harness.
- [ ] Include `Makefile`, `README.md`, project scripts, tests, and the documentation needed to build and audit the project.
- [ ] Include supplied helper files only in their original form, plus the required test20 CSV/expected output and the team’s group configuration.
- [ ] Include the required benchmark raw/summary files, perf raw output and summaries, and run manifests that support claims in the report. Preserve their original contents.
- [ ] Include `plots/signals.dat` and `plots/signals.png`.
- [ ] Include the actual Pi compiler-generated assembly, its matching manifest, and reviewed annotation if the Pi evidence is available. Do not substitute laptop assembly.
- [ ] Include completed report PDF, approximately 15-minute group presentation/video, and approximately 5-minute laptop/Pi race and LED demo video.
- [ ] Complete and include each member’s signed declaration/Own Work form. Complete the separate peer evaluation submission as instructed.
- [ ] Complete at least six dated and member-signed prediction/measurement/explanation entries, including at least one per stage, and include them in the report or required submission location.

## Safe pre-ZIP review

1. Run `python3 scripts/project.py readiness` and resolve source/layout defects. Treat Pi-only checks as `PI EVIDENCE REQUIRED / NOT LOCALLY VERIFIED` until the actual Pi files are present and inspected.
2. Compare every reported number and platform claim in the report against its original raw file and manifest. Keep laptop and Pi evidence distinct, and retain slower or inconclusive outcomes.
3. Exclude generated `build/`, `__pycache__/`, and `.pyc` files if the clean source can rebuild them. Do not exclude source, tests, required supplied files, plots, or evidence needed to support report claims.
4. Inspect the proposed file list manually for personal/temporary files and confirm that required evidence has not been omitted. Do not remove suspicious files solely because an automated check flagged them.
5. After the team creates the ZIP manually, extract it into a clean temporary directory on the Pi. Run `make`, the project test command, and test20 verification there; inspect the extracted inventory before submission.

No ZIP is generated by this repository workflow. The team must review and assemble it manually.

## Still manual

The report, videos, signed forms, peer evaluation, completed logbook, final evidence selection, and clean Pi extraction/build review cannot be marked complete by the readiness command.
