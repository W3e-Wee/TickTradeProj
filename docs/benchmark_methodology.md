# Benchmark methodology

- All versions are built with GCC and retain exact command/source/compiler metadata beside each executable.
- Benchmarking is refused unless test20, dev, and full stress signals/OHLC agree with frozen v1. Naive SMA variants also maintain a running-double crossover shadow because re-add summation can otherwise move equality crossings through floating-point rounding.
- Stress timings use at least five process-level repetitions with no trace, plot, or per-trade output. The runner retains raw wall time, count/load/compute phases, median, throughput, source/compiler/dataset hashes, logical allocation, and process peak memory.
- `logical_allocated_bytes` is the array/ring reservation or exact payload size; it is not an OS memory measurement. The process metric is `peak_working_set` on Windows and `ru_maxrss` on Unix-like systems.
- Frozen Version 0 is the debug `-O0` whole-file baseline. Speedups use median end-to-end process time and preserve non-monotonic results.
- The canonical `BuildSpec` records baseline/variant flags, compile sources, dependent headers, output paths, selections, and profile markers. `build-all` and `make all` use the same Python driver so sidecar validation checks the command that was actually built.
- For a Pi run, use `python3 scripts/project.py build-all`, `python3 scripts/project.py test --suite quick`, `python3 scripts/project.py verify --all-versions`, then the final-controlled benchmark command documented in `docs/performance_methodology.md`.
- Optional pinning (do not change affinity/governor automatically): `taskset -c 3 python3 scripts/project.py benchmark --dataset stress_full --repeats 5`. Record the current governor with `cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor`; benchmark rows also capture it when exposed by the OS.
- `make all` builds Stage 0 debug/release, v0/v1, v2-v10, eleven replay targets, and the replay-support C test executable. `make soa` builds only the separate v10 SoA executable. `make clean-build` removes only `build/`; it leaves datasets and all result evidence untouched. `make verify` and `make test` are also available.
- v10 is a new offline version; it does not replace any v0-v9 build or result. Its replay target is explicitly compatible at the strategy/input level, but timestamp replay uses its independent streaming storage backend rather than the offline SoA arrays.
- The fair offline AoS/SoA comparison is v9 versus v10: both use the manual digit-walk parser, running double SMA, double prices, `-O2`, the same dataset and windows, and exact two-pass count/load plus compute timing. The smaller SoA payload may reduce bytes fetched, while its separate memory streams may hurt locality; both are hypotheses, not results. The comparison table and graph preserve slower SoA results as measured.
- On the Pi, a new five-repeat controlled comparison uses a unique evidence directory and does not overwrite prior final-controlled data: `python3 scripts/project.py benchmark --dataset stress_full --repeats 5 --versions v0_baseline_strtok_running_double_heap_O0,v9_manual_running_double_exact_malloc_trade_array_O2,v10_manual_running_double_soa_O2 --platform-label pi-soa-aos-final --taskset-cpus 3 --final-controlled`.
