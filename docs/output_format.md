# Output format

## Engine console output

Engine programs print a human-readable heading, exactly one machine-readable line, then a final `PASS` or error. The result format is implemented in `src/common/result.c`:

```text
RESULT version=<id> file=<name> trades=<n> short=<n> long=<n> vwap=<%.6f> bars=<n> buys=<n> sells=<n> signal_hash=<16 hex> load_ns=<n> process_ns=<n> total_ns=<n> peak_mem_kb=<n>
```

The signal hash is FNV-1a 64-bit over each one-based trade index encoded as eight little-endian bytes, followed by the side byte (`1` for BUY, `255` for SELL). Cross-version checks require exact equality for trade count, bars, signal counts and hash; VWAP uses relative tolerance `1e-6`.

## Generated CSV schemas

CSV writers create a header when the file is empty and append later rows unless stated otherwise.

| Output | Header | Source and write behavior |
| --- | --- | --- |
| `results/bench/stage0_sum.csv` | `opt_level,mode,n,repeats,best_ns,median_ns,worst_ns,ns_per_add,sum` | `src/stage0/stage0_sum_loop.c`; appends. |
| `results/bench/stage0_recursion.csv` | `opt_level,mode,n,reps,batches,iterative_median_ns,recursive_median_ns,ratio` | `src/stage0/stage0_sum_recursion.c`; appends. |
| `results/bench/parser.csv` | `file,rows,repeats,sscanf_median_ns,fast_median_ns,speedup` | `src/stageA_plus/parser_compare.c`; appends. |
| `results/bench/ladder_<platform>_<member>.csv` | `platform,member,version,file,trades,repeats,median_total_ns,best_total_ns,worst_total_ns,median_process_ns,trades_per_sec,peak_mem_kb,compiler,flags` | `src/ladder/engine.c` and `src/stretch/soa/v9_soa.c`; `make bench` appends a warm-up-adjusted row for each rung. |
| `results/bench/memory_<platform>.csv` | The ladder header above | `make memory`; appends one measured row per engine with one recorded repeat after its discarded warm-up. |
| `results/replay/<platform>_<member>_<core>_<speed>x.csv` | `platform,member,core,speed,trades_replayed,market_seconds,wall_seconds,avg_latency_ns,worst_latency_ns,p50_latency_ns,p99_latency_ns,avg_processing_ns,max_lag_us,pct_behind,dropped_events,buys,sells,pnl_vs_rival_r1` | `src/stageC/replay_cli.c`; replaces the selected run file. |
| `results/replay/summary_<platform>_<member>.csv` | Same replay header | `src/stageC/replay_cli.c`; appends every selected core and speed run. |
| `results/rival/sweep.csv` | `platform,member,reaction_us,pnl,money_lost,trades` | `src/stageC/rival_sweep.c`; replaces the sweep file. |
| `results/bench/c_vs_python.csv` | `platform,member,implementation,file,trades,short,long,limit,repeats,median_total_ns,c_total_ns,times_slower_than_c,matches_c,python_version,numpy_version` | The two Python stretch programs; append their respective C/pure/NumPy rows. |

Python reports `peak_mem_kb=NA` in its own RESULT lines because it uses no nonstandard process-memory package. The C row in the Python comparison is a single C run; the ladder CSV contains repeated medians.

## Plot data and artifacts

- `results/plots/signals.dat` has no header; its columns are `trade_index,price,short_sma,long_sma,signal`. `src/stageA/stageA_stream.c` replaces the data file for the selected slice.
- `results/plots/signals.png`, `results/plots/money_lost.png`, and `results/plots/ladder.png` are generated by the matching gnuplot programs when gnuplot is installed. The ladder plot consumes the latest-row-per-version LF-only copy `results/bench/ladder_plot_input.csv`; the original platform/member benchmark CSV remains unchanged.
- `results/logs/data_profile.txt` is replaced by `make profile-data`; it reports the observed ranges and fixed-point bounds for the chosen input files.
- `results/asm/<core>_<arch>.s` is replaced by `make asm` using the host compiler's assembly output.

## Result interpretation

Use the same input, windows, platform and compiler settings when comparing timings. Use `median_total_ns` for end-to-end ladder comparisons and `median_process_ns` for the processing-only view. Replay latency is decision time minus scheduled release time; processing time covers the engine step; lag is nonnegative lateness. The replay record includes p50/p99 latency, worst latency, maximum lag and the fraction of decisions after release.
